# عقار Match — Aqar Match

منصة مطابقة عقارية جزائرية ذكية (Matching Platform) وليست لوحة إعلانات:

- **البائع** ينشر عقاراً بـ«سعر مطلوب» + «حد أدنى سريّ» (`secretMin`) لا يُكشف أبداً — لا في الواجهة ولا في أي استجابة API.
- **المشتري** يدخل طلب بحث بميزانية قصوى.
- **محرك مطابقة رباعي الطبقات** يُخرج أفضل 10 تطابقات فقط (الحد الأدنى للعرض: 65 نقطة).
- **كشف التواصل** فقط بعد موافقة البائع ودفع الرسوم (على البائع فقط — المشتري مجاني حالياً)، ثم دفع المشتري.
- **ثنائية اللغة**: العربية (RTL، افتراضية) والفرنسية (LTR) عبر `/fr` + كشف تلقائي.
- **النطاق الجغرافي**: 7 ولايات (الجزائر، البليدة، المدية، وهران، سطيف، قسنطينة، عنابة) مع كل بلدياتها الرسمية الـ256.

## المكدس التقني

| الطبقة | التقنية |
| --- | --- |
| الإطار | Next.js 16 (App Router) + TypeScript صارم 100% |
| قاعدة البيانات | PostgreSQL + Prisma 6 |
| التصميم | Tailwind CSS v4 + shadcn/ui (تُضاف المكوّنات تدريجياً) |
| التدويل | next-intl 4 (توجيه بالبادئات + RTL/LTR) |
| الحالة | Zustand |
| الصور | sharp — تحقق بالمحتوى + إعادة ترميز WebP وتجريد EXIF |
| الخطوط | Cairo Variable (عربي) + Inter Variable (لاتيني) — مستضافة ذاتياً عبر Fontsource |

## التشغيل المحلي

```bash
# 1) التبعيات
npm install

# 2) قاعدة البيانات
docker compose up -d db
cp .env.example .env

# 3) الترحيلات + البذر (الولايات والبلديات)
npx prisma migrate dev --name init
npm run db:seed

# 4) التطوير
npm run dev
```

- الواجهة العربية: `http://localhost:3000` — الفرنسية: `http://localhost:3000/fr`
- فحص الأنواع: `npm run typecheck` — الفحص الآلي: `npm run lint`

## النشر (standalone)

`npm run build` يُنتج حزمة `.next/standalone` مكتفية ذاتياً:

```bash
cp -r .next/static .next/standalone/.next/static
cp -r public .next/standalone/public   # عند إضافة أصول عامة
# المرفوعات (المرحلة 4): قرص دائم قابل للكتابة يُركَّب هنا — وإلا فُقدت عند إعادة النشر
mkdir -p .next/standalone/public/uploads
node .next/standalone/server.js
```

متغيرات البيئة المطلوبة في الإنتاج: `DATABASE_URL` و `NEXT_PUBLIC_APP_URL` و `OTP_PEPPER`.

> **المرفوعات**: الصور تُحفظ في `public/uploads/` (يتم إنشاؤها تلقائياً عند أول رفع) بعد
> إعادة ترميزها WebP وتجريدها من EXIF/GPS. في الإنتاج، اركب وحدة تخزين دائمة
> (Volume) على ذلك المسار. الصور اليتيمة (رفع بلا نشر مكتمل) تُكنَس عبر
> `POST /api/uploads/sweep` (إدارية، مهلة 24 ساعة) — جاهزة للجدولة الدورية.

## نقاط التكامل المطلوبة بعد الإطلاق

المنصة جاهزة وظيفياً بمحاكيات آمنة مغلقة الفشل؛ ما يلي ما يجب تركيبه عند الإطلاق الحقيقي
(كل بند له نقطة تركيب واحدة موثّقة في موضعها):

| البند | الموضع | المطلوب |
| --- | --- | --- |
| **بوابة الدفع الجزائرية** (رسم البائع) | `src/lib/matches/service.ts` ← كتلة «نقطة تكامل الدفع» + المتغيرات `PAYMENT_*` | SATIM (CIB/EDAHABIA) أو BaridiMob/CCP موثَّق. قواعد غير قابلة للمساومة: لا انتقال إلى كشف التواصل إلا بعد webhook موقَّع، والدفعة تبدأ `PENDING` لا `PAID` |
| **مزوّد SMS / WhatsApp Business API** (رمز OTP) | `src/lib/auth/otp-sender.ts` + المتغيرات `SMS_*` / `WHATSAPP_*` | قالب authentication معتمد؛ الفشل يبقى مغلقاً (503 صريح) — المحاكاة `OTP_MOCK` لا تُفعَّل في الإنتاج |
| **إشعارات واتساب للطرفين** | `src/lib/matches/service.ts` ← مواضع `notification.create` | إشعار خارجي موازٍ عند MATCH_FOUND وCONTACT_REVEALED، بقوالب معتمدة، ودون أي حقل محمي (لا `secretMin` ولا تفصيل النقاط حتى بعد الكشف) |
| **نظام الاسترداد** | عامل كنس دوري فوق مطابقات `EXPIRED` | إلغاء/استرداد تلقائي للدفعات المعلَّقة عند عدم استجابة البائع (void/refund) — يُبنى مع بوابة الدفع الحقيقية |
| **الجدولة الدورية** | `POST /api/matches/expire` + `POST /api/uploads/sweep` | cron خارجي أو Vercel Cron بجلسة admin أو مفتاح خدمة (`CRON_SECRET` عند اعتماد صلاحية خدمة) |
| **النسخ الاحتياطي والمراقبة** | خارج الكود | pg_dump مجدول + اختبار استعادة دوري؛ تنبيهات على `/api/stats` وسجلات `[api]` و`[audit]`؛ Sentry أو ما يكافئه |
| **لوحة إدارة داخلية** | نقاط إدارية جاهزة (`GET /api/properties`, `/api/matches/expire`, `/api/uploads/sweep`) محمية بدور `admin` | واجهة مراجعة: توثيق الوكالات (`isVerifiedAgency`)، الإشراف على الإعلانات، مراقبة المطابقات والرسوم |
